### New finding: Fabric handbook smoke check races resource readiness

The [failed Fabric job](https://github.com/chedidandrew/The_Emerald_Standard/actions/runs/34305387304/job/102322001997) records:

```text
java.lang.IllegalStateException: Emerald Handbook pages exceed the written-book limit of 14 lines
at ClientSmokeSupport.verifyHandbookPagesFit(ClientSmokeSupport.java:74)
at ClientSmokeSupport.lambda$initialized$1(ClientSmokeSupport.java:32)
```

The first reported overflow is page 2 at 50 lines. The diagnostic contains untranslated `book.the_emerald_standard.handbook...` keys rather than the intended handbook prose. The log shows client initialization, then initial resource/font loading, then this check.

Source inspection of [ClientSmokeSupport.java](https://github.com/chedidandrew/The_Emerald_Standard/blob/58b4cd0d12db85a38afd1299ce4650ee1d9cb56b/common/src/client/java/com/chedidandrew/emeraldstandard/client/ClientSmokeSupport.java) confirms that the helper sleeps for a fixed eight seconds after client initialization before scheduling the font-based validation. It does not explicitly await the initial resource reload or translated-language readiness. Both downloaded playable JARs contain the same 120 handbook translation keys, including the keys printed in the failure.

**Interpretation:** running the test before translations become available is the leading explanation. This has not been confirmed by changing the helper and rerunning CI. Do not dismiss the failure as fixed, and do not misidentify the unrelated missing Linux narrator library as its cause.

The exception is behind the `the_emerald_standard.clientSmoke` system property. Normal launches return before this code path. Therefore this failure alone does not demonstrate that the ordinary Fabric mod crashes on launch, nor that the translated handbook is actually 50 lines long. It does mean that the Fabric client validation is not green for this commit.

Recommended repair: gate handbook validation on completed resource/language/font readiness with a bounded timeout, verify a known translation resolves before measuring all pages, and retain the real overflow assertion. Increasing an arbitrary sleep or suppressing the error would not establish correctness.

## Previous concerns that remain open

### Inventory recovery isolation

The extracted `BankTransactionCoordinator.java`, `BankingOperations.java`, and `BankInventory.java` are byte-for-byte unchanged from the previously reviewed source archives. In particular, `BankTransactionCoordinator` retains Git blob SHA `cb8becb4dc3a96efa91762bfc5a3573c018816ab`.

A withdrawal can deliver items before its verified player checkpoint fails. Later recovery compares the current total item count against a historical expected count. Ordinary item transfers while that journal remains pending can therefore be mistaken for an incomplete delivery. The inspected recovery paths do not establish general inventory isolation.

This remains a source-derived failure scenario, not an exploit reproduced in Minecraft during this review. It still requires failure-injection integration tests covering chest transfer, dropping and pickup, death, reconnects, and repeated recovery, together with a provenance or isolation strategy.

### Whole-economy save cost

`EconomyService.mutatePlayer` still performs synchronous durable saving through `saveState`, which calls `state.save(path)`.

The [new common-job log](https://github.com/chedidandrew/The_Emerald_Standard/actions/runs/34305387304/job/102320896383) reports this mature fixture:

```text
accounts=100 history=365 ledger=128 positions=16 fund_entries=256
save_ms=737 replacement_save_ms=872 load_ms=1063 bytes=14946241
```

These are fixture timings on that CI runner, not observed gameplay lag or a measured end-to-end transaction. They remain a credible scaling concern for synchronous interaction paths. Do not interpret differences from the previous run as controlled performance gains or regressions across different runner environments.

### Hands-on evidence and maintenance

The current manual matrix still records `Not run` for its financial, GUI, migration, and multiplayer checks. The added format-18 upgrade and Banker-lifecycle rows expand the required evidence rather than completing it.

Several important classes have also grown: BankerScreen has 3,108 lines, EconomyService 4,976, VillageProsperityManager 6,512, and AuthoredVillageStructures 13,090 in the reviewed source archive. File size is not a correctness defect, especially for authored geometry, but separate page, persistence, lifecycle, and template responsibilities would make future changes easier to review.
